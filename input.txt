User: pip, what's the difference between a process and a thread?
Pip: A process has its own memory space and resources. A thread lives inside a process and shares its memory with sibling threads. Threads are cheaper to create and communicate faster, but they can corrupt each other's data if you aren't careful with locks.
User: So when would I pick processes?
Pip: When you need isolation or you want to use multiple CPU cores in a language with a global interpreter lock, like Python. Processes avoid that lock because each one has its own interpreter. The cost is more memory and slower message passing.

Pip: Threads or async tasks are usually fine there, since most time is spent waiting. Async is often the simplest model for lots of concurrent connections, as long as nothing in the path blocks the event loop.

User: Can you explain what a mutex is?
Pip: A mutex is a lock that only one thread can hold at a time. When a thread wants to touch shared data, it takes the lock, does its work, then releases it so the next thread can proceed.

User: pip, can you explain what a neural network is in a few sentences?
Pip: A neural network is a stack of simple math units that each take inputs, multiply them by learned weights, and pass the result through a small nonlinear function.
